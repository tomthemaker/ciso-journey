## Access method, limits and receipts

The web text parser still received Fedlex's JavaScript shell and EUR-Lex's robot-verification page at original/PDF locators. Indexed snippets are partial and potentially stale; they are not the retrieval evidence below. A clean ephemeral cached Chromium context loaded normal Fedlex pages and exposed the actual public filestore HTML/XML/download links. The six HTML links below came from those successful page requests, not constructed filename guesses. The [official public Fedlex SPARQL endpoint](https://fedlex.data.admin.ch/sparqlendpoint) also returned metadata identifying the two consolidated works, their original AS works and dated versions; it is metadata, not a substitute for the retrieved text.

For the EU, the [Publications Office's documented publication service](https://op.europa.eu/en/web/cellar/cellar-data/publications) supports public CELEX content negotiation. Requests to the four `https://publications.europa.eu/resource/celex/{CELEX}` URLs above used `Accept: application/xhtml+xml` and `Accept-Language: eng`, following the service's redirects to the exact CELLAR files below. The observed final redirects used HTTP; these byte hashes identify that response and are not a cryptographic authenticity or signature check. No login, challenge bypass or unofficial mirror was used. Retrieval succeeded independently of the still-challenged EUR-Lex presentation route.

All thirteen successful file responses were HTTP 200, with HTML content types for CH and `application/xhtml+xml;charset=UTF-8` for EU. Full bodies were downloaded outside the repository; titles/headings, edition markers and complete closing markup were checked, and all seven EU bodies parsed as XML. Only metadata and SHA-256 receipts are retained here, with no law files or learner data committed. Hashes are for the exact response bytes on the check date, not a promise of stable serialization.
