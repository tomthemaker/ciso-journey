# Quarterly self-assessment and portfolio

Issue [#17](https://github.com/tomthemaker/ciso-journey/issues/17). In Competencies, add optional evidence metadata (title, HTTPS reference and private notes), then append a dated self-assessment for one of the six existing competencies. The date determines its displayed calendar quarter. A correction or a later quarter is another entry; prior entries stay intact. The scope and rationale describe what the chosen Recognize, Explain, Apply or Lead level actually covers. Optional references point to portfolio evidence or an existing case response, retaining its exact scenario and rubric revisions. These are learner judgments, not independent reviews, overall mastery, or averaged case-rubric ratings. The legacy 0–4 scores remain separately editable.

Evidence metadata and appraisal history reside locally and in full v1/v2-compatible backups; links may visit external hosts when opened. No binary upload is provided. Exports contain private notes and references. Do not commit real backups or evidence. `portfolio` schema version 1 has append-only evidence and appraisals, unique IDs, strict dates and enum/provenance validation, and references checked against the same snapshot. Unknown extension fields survive. Future or malformed portfolio data is rejected before replacing current state; storage failure preserves the form draft for retry. Historical case references retain their pinned versions even when content is unavailable.

Validation: `npm test`, `npm run typecheck`, `npm run build`, and `npm run test:browser` (including Pages subpath); actual candidate and results are recorded in the PR. Fixtures contain synthetic data only.
